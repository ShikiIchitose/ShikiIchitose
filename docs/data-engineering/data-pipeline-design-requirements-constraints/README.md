# 要件と制約から考えるデータパイプライン設計

## 4つのCaseで比較する処理経路・保存基盤・再処理・運用

このディレクトリは、データパイプラインの構成をデータ量や製品名だけから選ぶのではなく、利用目的、データの特性、鮮度、信頼性・再処理要件、運用体制、ガバナンス、コストなどの要件と制約から考えるための学習・参照用資料です。

個人ポートフォリオで観察したDuckDBとBigQueryの実行時間差を出発点として、データパイプラインの設計を変える共通の評価軸を整理し、異なる条件を持つ4つの仮想事例（Case）を比較しています。

本資料では、主に次の構成を扱います。

1. 小規模・限定用途のマネージドサービス中心基盤
2. 複数部門・複数ソースを扱う成長中のバッチ基盤
3. 変更データキャプチャ（Change Data Capture: CDC）・イベントを扱う低レイテンシ基盤
4. 多様なデータと複数ワークロードを扱う共通データ基盤

各Caseでは、組織条件と要件、構成と設計判断、運用、トレードオフ、変更トリガーを整理します。また、4つのCaseを横断的に比較し、どの条件が処理経路、管理方法、保存・処理基盤、復旧設計を変えるのかを確認します。

## 想定する読み手

- データパイプラインやデータ基盤の設計を学び始めた人
- データエンジニアリング、アナリティクスエンジニアリング、データモデリングに関心がある人
- データウェアハウス中心のバッチ基盤と、低レイテンシ処理やレイクハウスとの違いを整理したい人
- フルリフレッシュ、増分処理、変更データキャプチャ、ストリーム処理の使い分けを理解したい人
- 障害検知、部分再実行、バックフィル、リプレイなどの再処理設計を整理したい人
- 技術構成だけでなく、運用体制、責任分界、コスト、保守可能性を含めて構成を検討したい人
- 異なる組織やワークロードに対して、どのような評価軸で設計を考えるべきかを確認したい人

## 資料の位置づけ

この資料は、データパイプラインの設計に関する理解を整理するために、個人が公開情報を調査して作成した学習・参照用資料です。

個人ポートフォリオで得られた観察を調査の出発点としていますが、実データ、実組織、長期運用の環境で、本文に示すすべての構成を実装・運用した実績を主張するものではありません。

また、4つのCaseは、すべてのデータパイプラインを網羅的に分類する体系ではありません。Case 1からCase 4へ順番に発展する成熟度モデルや、技術的な高度さ、企業規模、組織の成熟度による序列でもありません。

各Caseは、異なる要件と制約によって、必要な処理経路、保存・処理基盤、再処理方法、運用能力がどのように変わるかを比較するための仮想的な参照例です。実際のデータパイプラインは、いずれかのCaseと完全に一致するとは限らず、複数のCaseに近い特徴を持つ場合や、本資料では扱っていない要件・構成を含む場合があります。

本資料に示す構成図、処理方式、製品・サービス名は、特定製品の組み合わせを標準構成、推奨テンプレート、または唯一の正解として提示するものではありません。

実務へ適用する場合は、事業目的、対象データ、既存システム、セキュリティ・法規制上の条件、予算、責任分界、運用体制などを確認し、対象となる環境に応じて判断する必要があります。

第三者機関、標準化団体、資格認定団体、企業、製品ベンダーなどによって、内容が保証・監修・認証されたものではありません。

資料の調査の出発点、目的、対象範囲、公開情報の扱いについては、[chapters/00-introduction.ja.md](chapters/00-introduction.ja.md) を参照してください。
